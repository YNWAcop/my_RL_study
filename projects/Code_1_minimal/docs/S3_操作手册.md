## 0. 开工前必须知道的三个坑

### 坑 1：不给 `--exp-name`，TensorBoard 里七条曲线全叫 `ppo`

`ppo.py:19` 的 `exp_name` 默认取文件名，所以七个实验的 run 目录是：

```
CartPole-v1__ppo__1__<时间戳>     ← 七个实验全这样，只能靠时间猜
```

**每个实验必须给不同的 `--exp-name`**，才会变成：

```
CartPole-v1__S3_01_no_clip__1__<时间戳>
CartPole-v1__S3_02_loose_clip__1__<时间戳>
```

### 坑 2：`ref/` 被 `.gitignore` 忽略，`git diff` 看不到你改的源码

已验证：

```
$ git check-ignore -v ref/cleanrl/cleanrl/ppo.py
.gitignore:2:ref/    ref/cleanrl/cleanrl/ppo.py
$ git ls-files ref/
(空)
```

清单里写的「改完记得 `git diff` 确认」是错的 —— `ref/` 根本没进 git，改了什么 `git diff` 都不会显示。

**正确做法**：跑第 6、7 条这种改源码的实验时，先 `cp ppo.py ppo.py.orig`，跑完 `cp ppo.py.orig ppo.py` 还原。或者复制成独立文件（见 §2.6 / §2.7）。

### 坑 3：第 6、7 条其实都有命令行等价写法

`tyro` 会把 dataclass 字段自动生成为命令行参数。`--help` 实测有：

```
--norm-adv, --no-norm-adv      Toggles advantages normalization (default: True)
--max-grad-norm FLOAT          the maximum norm for the gradient clipping (default: 0.5)
```

所以 **7 个实验里有 6 个纯命令行就能做**，只有第 7 条想要「完全不裁剪」才需要动源码。
清单里第 6 条贴的代码也过时了 —— 实际变量名是 `mb_advantages`，不是 `advantages`。

## 2. 逐条详解

### 2.1 clip 关掉（`--clip-coef 0.0`）

```bash
"D:/envs/conda-envs/paper/python.exe" ref/cleanrl/cleanrl/ppo.py \
  --total-timesteps 500000 --seed 1 --exp-name S3_01_no_clip --clip-coef 0.0
```

涉及代码 `ppo.py:270`：

```python
pg_loss2 = -mb_advantages * torch.clamp(ratio, 1 - args.clip_coef, 1 + args.clip_coef)
```

`clip_coef=0` 时 clamp 区间是 `[1, 1]`，`ratio` 全被压成 1，`pg_loss2 = -mb_advantages`，
与 `ratio` 彻底脱钩 → `max` 恒取 `pg_loss2` → **梯度变成 0，策略完全学不动**。
预期：return 曲线几乎平在 20 左右。

> 注意这和「无裁剪」不是一回事。真正的无裁剪是 `--clip-coef` 极大（见 2.2）。

### 2.2 clip 放到极松（`--clip-coef 5.0`）

```bash
--exp-name S3_02_loose_clip --clip-coef 5.0
```

clamp 区间变成 `[−4, 6]`，实际永不触发 → 退化为「信任域为零」的原始策略梯度。
预期：仍能学，但震荡更剧烈，`approx_kl` 明显抬高（会到 0.01 以上）。

### 2.3 熵系数归零（`--ent-coef 0.0`）

```bash
--exp-name S3_03_no_entropy --ent-coef 0.0
```

对应 `ppo.py:289`：

```python
loss = pg_loss - args.ent_coef * entropy_loss + v_loss * args.vf_coef
```

`ent_coef=0` 后熵项消失，策略随机性只降不升。
预期：`losses/entropy` 单调掉向 0（基线会停在 0.51），早期可能收敛更快，但后期更容易卡在次优策略。

### 2.4 采样量砍到 1/8（`--num-steps 16`）

```bash
--exp-name S3_04_tiny_batch --num-steps 16
```

连带效应（`ppo.py:131-133`）：

```
batch_size     = 4 env × 16 步 = 64      （原来 512）
minibatch_size = 64 // 4      = 16      （原来 128）
num_iterations = 500000 // 64 = 7812    （原来 976）
```

iteration 数暴涨 8 倍，但每轮只采样 16 步，单轮开销反而更小。
**实测 500k 步耗时约 5.3 分钟，与基线基本持平**，SPS 仍在 1500 以上，不会明显变慢。
预期现象：方差大幅上升，return 曲线锯齿严重。

### 2.5 只更新 1 轮（`--update-epochs 1`）

```bash
--exp-name S3_05_single_epoch --update-epochs 1
```

对应 `ppo.py:248` 的 `for epoch in range(args.update_epochs)`。
同样 512 条数据，从「用 4 遍」变成「用 1 遍」，样本效率降到 1/4。
预期：收敛变慢，需要更多步数才能到 400；但由于数据复用少，单步更新更保守。

### 2.6 关优势归一化

**推荐做法（命令行）**：

```bash
--exp-name S3_06_no_normadv --no-norm-adv
```

`--no-norm-adv` 等价于让 `ppo.py:265` 的 `if args.norm_adv:` 恒为 False，跳过 266 行。

**想看清代码（改源码）**：`ppo.py:264-266`

```python
                mb_advantages = b_advantages[mb_inds]
                if args.norm_adv:
                    mb_advantages = (mb_advantages - mb_advantages.mean()) / (mb_advantages.std() + 1e-8)
```

把 265–266 行注释掉即可。注意清单里写的 `advantages = (advantages - advantages.mean()) / (...)` 是旧版变量名，当前代码是 `mb_advantages`。

预期：CartPole 奖励恒为 +1，优势数值本身就在合理量级，**这条可能差异不明显**——
真跑不出差异也是有效结论，写进表格就是「该任务对本项不敏感」。

### 2.7 关梯度裁剪

**推荐做法（命令行近似）**：

```bash
--exp-name S3_07_no_gradclip --max-grad-norm 1e9
```

`ppo.py:293`：

```python
nn.utils.clip_grad_norm_(agent.parameters(), args.max_grad_norm)
```

CartPole 的梯度范数实测在个位数到几十，`1e9` 永远碰不到，等价于不裁剪。

**想严格关掉（改源码）**：把 293 行注释掉。但不要用 `--max-grad-norm 0`，
那会把所有梯度按比例缩到范数 0，等于把网络彻底冻结。

预期：偶尔出现尖峰更新，`value_loss` 抖动加剧，严重时 return 中途崩掉再恢复。

## 3. PyCharm 里怎么跑

### 3.1 建一个可复用的 Run Configuration

```
右上角运行配置下拉 → Edit Configurations... → + → Python

  Name:             S3_01_no_clip
  Script path:      D:\Papers\Code\ref\cleanrl\cleanrl\ppo.py
  Parameters:       --total-timesteps 500000 --seed 1 --exp-name S3_01_no_clip --clip-coef 0.0
  Working directory: D:\Papers\Code          ← 必须改，见下
  Python interpreter: Python 3.12.15 ('paper')
```

⚠️ **Working directory 是这里唯一的坑**。`ppo.py:147` 写死了相对路径 `runs/{run_name}`，
如果工作目录停在 `ref/cleanrl/cleanrl/`，`runs/` 就会生成在那里，TensorBoard 扫不到。

### 3.2 复制配置做实验

把上面这个配置 `Ctrl+D` 复制七份，只改 `Name`、`--exp-name` 和那一个实验参数。
比每次手敲命令快，也不容易抄错。

### 3.3 跑起来后看什么

Console 里三类输出：

```
global_step=1234, episodic_return=215.0     ← 训练中的实时成绩
SPS: 1650                                    ← 吞吐，不看也行
（各种 UserWarning）                          ← 忽略
```

**200 万行刷屏时**可以关掉终端输出，直接看 TensorBoard。

## 4. TensorBoard 界面操作

### 4.1 启动

在 PyCharm 的 Terminal 里（确认工作目录是 `D:\Papers\Code`）：

```bash
"D:/envs/conda-envs/paper/python.exe" -m tensorboard.main --logdir runs --port 6006
```

浏览器打开 `http://localhost:6006`。端口被占用就换 `--port 6007`。

### 4.2 界面上的五个操作

| 操作 | 位置 | 用途 |
|---|---|---|
| 勾选 / 取消 run | 左栏 RUNS 复选框 | **七条曲线对比就靠这个**，只留基线和当前实验 |
| 平滑滑块 | 左栏 SMOOTHING | 默认 0.6，调 0.9 看长期趋势，调 0 看原始抖动 |
| 放大单图 | 卡片右上角 ⤢ | 全屏看清细节 |
| 导出数据 | 卡片右上角 ⋯ → Download as CSV | **写论文表格要用**，比截图靠谱 |
| 切换 x 轴 | 卡片上方 x 轴下拉 | `step` 是按 global_step，`relative` / `wall` 看别的维度 |

### 4.3 该看哪几个 tag

左栏会按 `charts/` 和 `losses/` 自动分组。S3 只需要盯三个：

| tag | 看什么 |
|---|---|
| `charts/episodic_return` | **主图**，七条曲线叠在一起，谁的曲线掉下来谁就有问题 |
| `charts/SPS` | 只有实验 4 会明显异常，其余七条应基本重合 |
| `losses/entropy` | 只有实验 3 会掉到 0 附近，其余停在 0.5 左右 |

其余 `losses/*` 是辅助，S3 表格里用不到就不必逐个截图。

### 4.4 一条重要提醒：别用平滑过度的图下结论

`SMOOTHING=0.9` 会把实验 4 那种剧烈震荡抹成一条平线，看起来「问题不大」。
**截图存档时把滑块调到 0 或 0.3**，并在图注里写明平滑值，否则组会上被问就答不上来。

## 6. 一键跑完全部（可选）

嫌手动点七次麻烦，可以存成 `scripts/run_s3.sh`：

```bash
#!/usr/bin/env bash
cd /d/Papers/Code
PY="D:/envs/conda-envs/paper/python.exe"
SCRIPT="ref/cleanrl/cleanrl/ppo.py"
COMMON="--env-id CartPole-v1 --total-timesteps 500000 --seed 1"

run () { echo "=== $1 ==="; "$PY" "$SCRIPT" $COMMON --exp-name "$1" "${@:2}"; }

run S3_00_baseline
run S3_01_no_clip      --clip-coef 0.0
run S3_02_loose_clip   --clip-coef 5.0
run S3_03_no_entropy   --ent-coef 0.0
run S3_04_tiny_batch   --num-steps 16
run S3_05_single_epoch --update-epochs 1
run S3_06_no_normadv   --no-norm-adv
run S3_07_no_gradclip  --max-grad-norm 1e9
```

总耗时约 40 分钟，各实验耗时相近（都在 5 分钟左右）。**第一次建议手动逐条跑**，
至少跑完前两条确认 TensorBoard 里曲线能正常区分，再交给脚本。
